# ADR 0001：共享学习核心与运行时边界

> 学习核心隔离的决策继续有效。首期旧 Popup bridge 已由[ADR 0002](0002-offline-library-and-sync.md)中的统一客户端取代；下文保留首期实施记录。

- 状态：首期已实现并通过自动检查；浏览器与升级验收待完成
- 日期：2026-10-03
- 背景提案：[多端架构 RFC](../architecture/2026-10-03-multiplatform-architecture-rfc.md)

## 背景

重构前，根 `manifest.json` 加载旧扩展 JavaScript 入口；根 `build` 只编译 `src/` TypeScript，构建产物没有闭合到扩展入口。复习规则与页面和旧数据路径存在耦合。未来希望支持扩展、Web 和移动端，本轮聚焦架构和现有运行时接线。

## 决策

先用 TypeScript 建立平台无关的学习调度核心，并在旧扩展运行时通过适配器调用它。使用 pnpm workspace 管理扩展和共享包；先补齐可重复的扩展构建，再逐步收拢学习规则。核心只处理明确的输入、输出和注入的时钟，不直接访问 Chrome、DOM、UI、网络或具体存储。现有扩展界面与交互方式保留。

## 首期验收

1. 当前工作区已按锁文件安装并统一构建出 72 个文件；干净检出和真实浏览器加载仍需复验。
2. 调度核心在无浏览器运行时的测试环境执行，使用显式时间输入验证真实业务规则。
3. 活跃 Popup 的 LearningManager 已调用核心；未加载的旧 ReviewQueueManager 保留为历史代码，不激活第二套规则。
4. 核心导入与直接平台引用的语法边界检查、打包入口和产物检查均通过。语法检查不是完整语义隔离证明。

`pnpm run check` 已通过，其中新测试为 5 个文件、46 个测试。完整结果和未验证范围见[首期验证记录](../architecture/phase-1-verification.md)。

## 后果与后续

短期需要兼容旧运行时数据结构并新增构建/适配层；部分扩展功能可以暂缓恢复。共享规则降低后续平台复制成本，但不提供跨端数据同步，也不使各端 UI 或数据库自动共享。

完整数据迁移、IndexedDB/outbox、云同步、Web 与移动端属于后续独立阶段。只有在首期真实使用并验证后，再决定领域模型、存储契约和服务端边界。若调度规则无法从旧数据无损表达，应先记录映射和差异，不静默更改用户进度。

当前仍使用 Chrome Storage 整对象写入。新的输出目录用于开发验证；切换加载目录可能改变扩展 ID，不能假定旧数据自动继承。保留原扩展与数据，并将备份恢复、原地升级和浏览器迁移验证列为后续验收。

## 重新评估条件

若学习规则必须依赖端特有行为、旧数据无法合理映射，或共享包导致扩展构建路径更复杂且不能形成可靠产物，则暂停扩展调用迁移，记录替代方案和证据后再修订本决策。
