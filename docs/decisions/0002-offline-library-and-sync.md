# ADR 0002：离线词库、复习事件与统一同步

- 日期：2026-10-04
- 状态：已实现；运行验收边界见[验证记录](../architecture/multiplatform-verification.md)

扩展、Web 和移动端需要离线保存并在登录后同步，继续让界面覆写整个 Chrome Storage 对象会产生并发覆盖和多份业务规则。

采用 `core → data → 客户端` 依赖方向。core 定义学习和同步规则；data 组织用例、迁移、备份和 outbox；浏览器和 SQLite 适配器只负责事务。扩展的活跃运行时改用 TypeScript entrypoints，并复用 Web 词库 UI。旧界面和第一阶段适配文件保留作历史资料与回归基线，不再打包运行。

词条 ID 由源语言和规范化文字决定。复习是独立事件，按事件时间和 ID 排序重放，沿用原有 1/2/4/7/14/30 天掌握度规则。迁移后的词条保存旧进度作为重放基线，完整旧数据保留在备份元数据中；原 Chrome Storage 不删除。

本地写入与 outbox 同一事务提交。同步采用用户隔离、mutationId 幂等、分页游标、删除墓碑，以及 updatedAt/deviceId/mutationId 决定的最后写入胜出规则。客户端时间偏差可能影响不同设备同时编辑同一词条的胜者；这不是字段级协同编辑。复习事件保留不可变原值，备份不能改写同一事件 ID。请求同时受记录数和 UTF-8 字节上限约束。

服务端是 Node 24 + SQLite 的单实例模块化应用。这个规模下无需分布式服务；需要多副本时，应先把数据库和事务迁移到支持共享写入的服务端数据库。当前不压缩同步日志，以保证长期离线客户端还能补齐删除和事件。

账号使用密码哈希和可撤销会话。匿名 `local` 与账号空间隔离，登录不会自动上传匿名内容。云端账号验证、密码重置和运维监控是后续产品/部署工作，不由基础同步协议提供。

Web/扩展用 IndexedDB；移动端用 SQLite 和 SecureStore。网络、凭据和平台 API 不进入 core。数据适配器可通过同一事务合同测试；UI 功能和样式可以在此边界上继续开发。
