## 自动检查

`EXPO_NO_TELEMETRY=1 pnpm run check:all` 已完成，退出码 0：

- core、data、API、Web、移动端、扩展 TypeScript 检查通过。
- core 导入与平台引用边界检查通过。
- 12 个 Vitest 文件、94 个测试通过，包含真实 HTTP、SQLite、IndexedDB、并发、迁移、离线重试和备份恢复测试。
- Web、扩展、API 构建与产物检查通过。扩展包包含 8 个文件，仅打包新运行时及共享 Web UI。
- Expo 实际导出 iOS 与 Android 的 Hermes bundle，通过原生平台打包流程；不是签名安装包或真机运行证据。

独立复查发现并修复三个问题：大词库批次超过 API 大小限制；篡改已知复习事件的备份导致 outbox 持续失败；重复恢复时重新引入已撤销导入的数据。新增回归测试分别覆盖真实 UTF-8 请求大小、SQLite 服务端不可变事件约束和重复恢复幂等。

## 实际 Web 与服务端验证

通过同一个 Ego 浏览器任务空间测试本机 Web 构建及本机 API，仅使用临时测试账号与数据：

1. 注册、登录、创建带语境的词条，并同步至 API。
2. 闪卡答对后进度为等级 1、复习 1 次，两个独立浏览器存储空间读取相同结果。
3. 模拟页面断网后新增词条，刷新后词条仍存在；恢复网络后 outbox 上传成功。
4. 使用 `127.0.0.1` 和 `localhost` 两个不同源、独立 IndexedDB 验证双向同步与收藏状态。
5. 下载真实备份，核对记录和复习原值；通过文件选择导入修改后的词条，再连续恢复两次。词条回到导入前状态，同步成功且页面无错误。

API 的 Docker 镜像构建通过；启动独立容器后完成健康检查、注册和词条同步。保留持久卷重建容器后，账号登录和之前保存的词条仍可用。临时测试容器与卷已清理。API 源码 watch 的重建和进程重启也已验证。

- 本机 `xcrun simctl list devices available` 返回空设备列表，未运行 iOS 模拟器或真机。Android 亦未进行设备运行验收。
- 未提供公网部署目标，因此交付 Docker/反向代理配置和已实测的持久化服务，没有创建公网服务。线上须配置域名、HTTPS 和部署环境。
