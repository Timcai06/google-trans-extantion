## 为什么没有整体覆盖

旧工作区实现了 2026-09-20 的单扩展 TypeScript 运行时，根级构建、独立 IndexedDB 模型、DeepSeek 直连和 React 功能页组成一套完整替换方案。当前 main 已实现多端共享学习契约、LibraryClient、同步服务、Web/扩展入口和 Expo 移动端。整体套用旧工作区的删除、移动和 package 配置会撤销后续多端开发。

本次只整合仍有用的数据迁移行为。原始未提交文件保持在本地工作分支中，不覆盖其他工作树正在进行的 Popup/UI 工作。

## 导入约束

- 原始数据库只在存在时打开，不指定升级版本；未知结构报错并保留原数据。数据读取在只读事务中完成，连接随后关闭。
- 新状态写入、outbox、来源标记和恢复快照沿用 LibraryStore 的原子事务。一次迁移不会生成虚构 review；旧事件、日期语义、上下文变体与原进度保存在备份归档。
- 旧文件按规范化内容生成可跨平台计算的标识。同一标识仍比较完整归档以拒绝身份冲突；它不是签名或可信来源证明。
- 旧来源只迁入一次。恢复快照后不会因后台重启自动重放旧来源；同一旧文件重复选择也不再次导入。不同旧文件分别留档。已经在新库删除的词条不会被迁移恢复。
- 历史进度由现有学习规则规范化；不添加第二套 scheduler。非法旧 JSON 在写入前拒绝；旧单条词条无法解析时沿用跳过计数。
